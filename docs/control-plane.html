Sweeper, Budget & Cancellation

The control plane: how dead executors are detected and retried, where every agent checks the project budget, and how a running agent actually finds out it has been stopped.

Nobody sends a kill signal. State changes in Postgres, and everyone discovers it through guards.

1 Leases and the sweeper

A guarded claim cannot recover a run whose executor died while holding it in running — nothing would ever move it again. Executors renew a lease (bump updatedAt) every 60 seconds; a scheduled sweep Lambda judges anything that stops.

Why 3 missed beats, not a 10-minute window

The old heuristic — "no row write in 10 minutes" — false-positived on any healthy segment longer than the window. A missing lease means the executor is gone, not that the segment is slow. Two tolerated misses keep a transient DB blip from failing healthy work.

Off its own failure domain

The sweeper runs in a separate scheduled Lambda, deliberately off the AgentCore runtime it recovers — a broken worker image or hung DB pool cannot take down its own crash recovery.

Idle rows keep the patient window

pending and waiting_on_children rows are held by nobody — no lease to renew, so staleness can't mean death. They get the 10-minute window: lost dispatches are re-sent, dropped-baton parents resumed.

3 How a running agent finds out it was stopped

The lead calls stopProjectAgent (or a user hits Stop). One guarded UPDATE flips the whole tree to cancelled — but the workers executing those runs are mid-LLM-turn on AgentCore and receive no signal at all. They discover it three ways.

Pickup 1 · the stop-signal poller

Every agent run has a background poller (createStopSignalPoller, 2s interval) checking its own run row. Row terminal → AbortController.abort() → the LLM stream halts mid-turn. The processor sees stopReason: "stopped", skips finishRun (guarded no-op anyway), and just EOFs the stream.

Pickup 2 · guarded transitions fail

A worker that already finished its turn tries yieldRun / finishRun — zero rows returned, because the status is cancelled, not running. The work is dropped silently. renewRunLease also returns false, telling the renewer there is nothing left to keep alive.

Pickup 3 · spawn refusal

spawnSubagents re-reads the parent before creating children: a terminal parent gets "This run has been stopped; no new sub-agents can be spawned." Without this, a cancelled orchestrator mid-turn could create unstoppable orphans.

The roster reset is race-safe

stopProjectAgent resets the roster row guarded on the exact activeRunId it cancelled — a concurrent start that already claimed the slot with a new run is never clobbered to idle. And if cancelRunTree cancelled zero rows (the run finished on its own first), the real result is preserved instead of stamping the cancelled stub over it.
