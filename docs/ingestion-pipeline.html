2 Design details worth knowing

Pointers, not payloads

Stages hand off multi-megabyte document text and infons via S3 artifacts in the semantic bucket — only small pointers travel through the state machine, staying well under Step Functions' 256 KB state limit.

Self-healing manifest

BuildManifest reconciles the S3 listing against Postgres: any object without a document row gets a pending row created for it. Direct-to-S3 uploads just work — no API call required.

Two statuses per document

indexStatus (vector) and graphIndexStatus (graph) are tracked independently. One branch can fail while the other succeeds — and only the failed one is retried on the next run, because the manifest skips already-indexed work per index.

Idempotent graph writes

WriteGraph MERGEs reified (:Infon) facts into Neptune over Bolt with SigV4-signed connections. Re-running a document converges on the same nodes instead of duplicating them.

Retries per stage

Each Lambda stage retries transient errors (Lambda throttles, Bedrock hiccups, States.TaskFailed) 3 times with exponential backoff before the branch is marked failed.

Who reads the indexes

Agents query LanceDB through queryDocuments (hybrid vector + BM25 + rerank) and Neptune through the graph tools (search, neighborhood, paths, overview). The web explorer reads the same graph.
