Knowledge Graph Writers & Provenance

Two writers feed one append-only substrate — the ingestion pipeline and the agents themselves. Every agent-written node is stamped with provenance the model never touches.

projectId, runId, and author are not tool inputs — the model can't be trusted to supply them.

1 Two writers, one substrate

Both write the same reified shape — (:Infon) facts between (:Entity) nodes via S_OF/O_OF — so agent-authored facts appear in every existing read tool and the explorer with zero extra plumbing.

🏭 Ingestion pipeline

verified_by = document

The Step Functions pipeline extracts triples from documents via Bedrock and MERGEs them into Neptune (write_graph.py). Facts carry their source document for citation.

  • Writes (:Infon) facts + (:Entity) nodes
  • Also writes the predicate ontology (advisory vocabulary)
  • Idempotent: re-running a document converges on the same nodes

🤖 Agents (during runs)

verified_by = agent

Persona and sub-agent runs write through the graph tools. Two distinct layers:

  • addGraphFact — factual triples, same (:Infon) shape as ingestion
  • recordObservation / recordHypothesis — reasoning nodes (:Observation, :Hypothesis)
  • The research loop reacts only to reasoning nodes, never raw facts — facts are the substrate that reasoning cites

3 Append-only, but never duplicated

infon_id = "agent:" + sha256(subject, predicate, object, documentId, projectId) — deterministic, so re-asserting a fact MERGEs onto the same node. But projectId is part of the key, so the same triple under two projects stays two independently-scoped facts.

Same triple, same project → MERGE

Same triple, different project → two facts
("Compound A", "inhibits", "Kinase X") · project 4a92
("Compound A", "inhibits", "Kinase X") · project b7e1
sha256 → agent:9f3c21… agent:47ad0e…

The graph is append-only from the agent's side: no upsert to rename an entity, no delete to remove a fact. A re-assert corrects in-flight polarity/confidence without duplicating — the identifying triple itself is frozen by the hash. Entities are created as a side effect of facts (MERGE (s:Entity)), so there is no separate entity-write tool. Off-vocabulary predicates are allowed but flagged (in_vocab), exactly like ingestion.

4 Who reads it back

The research loop

summarizeNewKnowledge / listNewKnowledge count :Observation and :Hypothesis nodes newer than project.knowledgeWatermarkAt — this is what powers the knowledge pulses and the lead's getNewKnowledge tool. Author attribution comes straight off the stamped nodes.

Persona agents

Read tools — search, neighborhood, paths, overview, epistemic-read — serve agents mid-run so they can cite existing facts and build on prior observations instead of rediscovering them.

The web explorer

The project-scoped graph view filters on the stamped project_id — agent facts and document facts render side by side because they share one shape.
